## Gemini API Key Handling (`CRITICAL`)

### 1. Client Bundle Warning (`vite.config.ts`)
Current `vite.config.ts` injects `process.env.API_KEY` and `process.env.GEMINI_API_KEY` at Vite build time (`define`) so the React SPA can call Google Gemini directly during **local single-user development**.

- **NEVER** publish a compiled `dist/` directory created with a real `GEMINI_API_KEY`.
- **NEVER** deploy this static frontend to a public host (GitHub Pages, Netlify, Vercel static export) with a shared `GEMINI_API_KEY` baked into the client bundle — anyone inspecting the built JavaScript could extract the key.
- Moving all Gemini API calls behind a backend proxy (`Stage G`, `PLANNED`) is required before any public multi-user web deployment.

### 2. Local Development & Agent CLI
- Store local Web UI keys only in `.env.local` (ignored by `.gitignore`). Copy `.env.example` to `.env.local`.
- Pass the CLI key at runtime via environment variable `GEMINI_API_KEY` (never as a hardcoded literal or CLI flag).
- Do not store keys in `localStorage`, JSON manifests, or prompt history.

## Secrets, Privacy & Asset Hygiene

The repository `.gitignore` explicitly excludes:
- `.env`, `.env.*` (except `.env.example`), `*.local`
- `node_modules/`, `dist/`, `dist-ssr/`
- `.venv/`, `book_layer/.venv/`, `__pycache__/`, `.pytest_cache/`
- `.aistudio/`, `migrated_prompt_history/`, `.local_backup/`
- `*.pdf` (local books and internal draft reports)

Contributors must verify `git status` and `git diff --cached` before committing to ensure no credentials, personal contact details, third-party copyrighted PDFs, or unverified binary media are staged.

---

## Educational & Textual Integrity Safeguard

PushkinRhymeEngine 2.0 enforces two domain integrity boundaries:
1. **Factual Accuracy:** Poetic form must never override factual accuracy (`POETIC FORM MUST NOT OVERRIDE FACTUAL ACCURACY`). Educational verse generated by LLMs requires human verification until deterministic verification modules exist (`PLANNED`).
2. **Source Validation (`source_validation`):** Scanned pages (`SCANNED_PAGE`), failed reads (`FAILED`), editorial commentary, and unclassified PDF line wraps (`PDF_TEXT_LINE_UNCLASSIFIED`) are programmatically blocked from prosodic analysis (`prosodic_analysis_allowed == False`).

## Reporting a Vulnerability

If you discover a security or data-leakage issue in this repository:
1. Do **not** post real API keys, tokens, or private data in public issues.
2. Open a private GitHub Security Advisory (when hosted on GitHub) or report the issue cleanly with reproduction steps and affected files without sensitive payloads.
