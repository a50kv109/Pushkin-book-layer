# PushkinRhymeEngine 2.0 (`v0.1.0-alpha`)

> **Предварительный открытый альфа-релиз (`Stage C+`):** PushkinRhymeEngine 2.0 — **открытый образовательный и творческий поэтический движок**, который помогает людям и ИИ-агентам выражать содержательные мысли, научные идеи и учебный материал в ритмически и художественно организованной речи.  
> **Граница честности:** На версии `v0.1.0-alpha` генерация стиха выполняется через промпт-ориентированный вызов Google Gemini (`transformText()`, живой API-вызов в текущей офлайн-среде **`NOT_VERIFIED`**). Рядом работают CLI для ИИ-агентов, метаданные визуально-нарративной библиотеки и изолированный Python-контур работы с книжными источниками (`/book_layer` + `/source_validation`). Детерминированные анализаторы метра, ударений, рифмы и фактологической точности (`C1`–`C8`, `M8`) находятся в статусе **`PLANNED`**.

---

## 1. Назначение и образовательная позиция проекта

PushkinRhymeEngine 2.0 задуман не как узкий имитатор одного стиля, а как **открытый образовательный и творческий инструмент**, обучающий выражению мысли в стихотворной форме.

**Поэтика А.С. Пушкина выступает здесь как важная исследовательская основа:** она помогает изучать, как точный смысл соединяется с ритмом, рифмой, интонацией и образом. Практические области применения:
- **Образование:** объяснение понятий математики, физики, химии, биологии и гуманитарных дисциплин через запоминающуюся стихотворную форму.
- **Творчество и музыка:** тексты песен, поздравительные открытки, философские миниатюры, литературные этюды.
- **Инструмент для ИИ-агентов:** единый контракт `transformText()`, CLI и спецификация `SKILL.md` для вызова внешними агентами.
- **Исследование источников:** строгое разделение художественной ИИ-генерации и текстологических свидетелей (`/book_layer` + `/source_validation`).

## 2. Базовый принцип: точность смысла прежде красоты рифмы

> **`POETIC FORM MUST NOT OVERRIDE FACTUAL ACCURACY`**  
> *(Поэтическая форма не должна подменять фактическую и научную точность.)*

При стихотворной переработке **учебных, научных и технических текстов** (математика, физика, химия, инженерия):
1. **Сохранять суть:** формулы, определения, физические законы, химические процессы, единицы и причинно-следственные связи не должны искажаться ради рифмы.
2. **Фиксировать упрощения:** любые художественные допущения или опущенные граничные условия должны явно помечаться как поэтическое упрощение.
3. **Обязательная проверка человеком:** пока не реализованы детерминированные семантические и фактологические проверки (`PLANNED`), образовательные стихи требуют проверки преподавателем или автором материала.

## 3. Шесть демонстрационных примеров использования

> **Статус примеров:** Ниже приведены **демонстрационные сценарии (`Demonstrative / NOT live-verified by Gemini API`)**, показывающие ожидаемую постановку задач для движка. Живой сетевой запрос к Gemini API в текущей среде без `GEMINI_API_KEY` не запускался.

1. **Математика (Теорема Пифагора):**  
   *Вход:* «В прямоугольном треугольнике квадрат гипотенузы равен сумме квадратов катетов: $c^2 = a^2 + b^2$.»  
   *Ожидаемый ориентир:* строфа с обязательным сохранением прямого угла (`90°`) и равенства $c^2 = a^2 + b^2$ и финальным пояснением применимости к евклидовой плоскости.
2. **Физика (Закон сохранения энергии):**  
   *Вход:* «В замкнутой системе полная энергия сохраняется: кинетическая и потенциальная энергия переходят друг в друга, не исчезая бесследно.»  
   *Ожидаемый ориентир:* стих с сохранением условия замкнутости системы и взаимопревращения форм энергии без ложных «вечных двигателей».
3. **Химия (Окислительно-восстановительная реакция):**  
   *Вход:* «Восстановитель отдаёт электроны и окисляется, а окислитель принимает электроны и восстанавливается.»  
   *Ожидаемый ориентир:* запоминающееся мнемоническое четверостишие, где направление передачи электронов передано без инверсии ролей.
4. **Песня / лирический текст:**  
   *Вход:* «Вечерний поезд уходит от тихой морской станции, унося воспоминания о летнем дожде и обещание вернуться.»  
   *Ожидаемый ориентир:* песенные строфы с ровным ритмом и перекрёстной рифмой (`ABAB`).
5. **Поздравительная открытка:**  
   *Вход:* «Тёплое поздравление с днём рождения коллеге, который любит астрономию и горные походы.»  
   *Ожидаемый ориентир:* лаконичное поздравление в классическом размере, объединяющее звёздное небо и горные тропы.
6. **Философская / научная мысль:**  
   *Вход:* «Любая научная модель — это карта, а не сама территория; знание границ модели делает знание прочнее.»  
   *Ожидаемый ориентир:* афористичная строфа о границе модели и реальности с итоговой моралью.

## 4. Что реализовано в `v0.1.0-alpha` (`IMPLEMENTED` / `TESTED`)

- **React / Vite Web UI и Gemini-сервис** (`App.tsx`, `OutputParchment.tsx`, `EngineVisualizer.tsx`, `services/geminiService.ts`): промпт-ориентированная генерация JSON `{ poem, moral }` через `gemini-3-pro-preview` (живой вызов **`NOT_VERIFIED`**). 6-шаговый `EngineVisualizer` — это визуальная анимация ожидания (`800ms`), а не отдельные анализаторы стиха.
- **Agent CLI & Skill** (`agent-interface/cli.ts`, `SKILL.md`, `skills/pushkin-rhyme-machine/`): команды `info`, `help`, `generate` (`--text`, `--input`, `stdin`, `--output`); **`4/4`** офлайн-тестов (`test_cli_agent_call.py`) пройдены. В `info` явно указано `programmatic_meter_validation: false`.
- **Visual & Narrative Reference Library V1** (`services/visualLibraryService.ts`, `components/visual-library/*`, `data/visual-library/*`): 19 метаданных визуальных якорей (11 категорий), 8 нарративных паттернов, 3 режима работы (конструктор брифа открытки, лексический подбор иллюстрации, сборка художественного контекста для `transformText()`), правки в `localStorage`.  
  *Примечание к публичному альфа-релизу:* 19 локальных AI-PNG временно исключены из публичного Git-релиза до подтверждения прав распространения медиафайлов (см. `public/assets/aistudio/README.md`). Интерфейс корректно работает в режиме метаданных и текстовых fallback-карточек без сбоев.
- **Book Layer** (`/book_layer`, Python `>= 3.10`, `PyMuPDF >= 1.24`): переносимый адаптер PDF с SHA-256 контролем, 1-индексированной физической пагинацией, обработкой `FAILED` и блокировкой `SCANNED_PAGE` на входе `pipeline.to_c1_input()`.
- **Source Validation** (`/source_validation`): независимый шлюз `SourceEvidencePackage` с раздельными флагами `semantic_analysis_allowed` и `prosodic_analysis_allowed` (блокирует `SCANNED_PAGE`, `FAILED`, `PARTIAL`, комментарии, прозу и неклассифицированные PDF-строки `PDF_TEXT_LINE_UNCLASSIFIED`).

## 5. Установка, запуск и тесты

```bash
# 1. Веб-приложение (локальная разработка)
npm install
cp .env.example .env.local
# Укажите свой GEMINI_API_KEY в .env.local (файл игнорируется Git)
npm run dev
```

> **Безопасность (`SECURITY.md`):** Текущий `vite.config.ts` подставляет `GEMINI_API_KEY` при сборке для локального использования. Не публикуйте статический `dist/` со встроенным ключом. Серверный прокси запланирован на Этап G.

```bash
# 2. CLI для ИИ-агентов (Node >= 22.6)
export GEMINI_API_KEY="your_api_key_here"
npm run pushkin-rhyme -- info
npm run pushkin-rhyme -- generate --text "Энергия в замкнутой системе сохраняется."

# 3. Офлайн-проверки перед публикацией / разработкой
npx tsc --noEmit
npm run build
python3 test_cli_agent_call.py

# 4. Python-контур Book Layer & Source Validation (13/13 автономных тестов)
python3 -m venv book_layer/.venv
book_layer/.venv/bin/pip install "PyMuPDF>=1.24"
book_layer/.venv/bin/python -m unittest -v book_layer/tests/test_synthetic_book.py source_validation/tests/test_source_validation.py

# 5. Опциональный тест на внешнем PDF «Бориса Годунова» (без BORIS_PDF пропускается)
BORIS_PDF=/path/to/pushkin_vyp2_boris_godunov_2008.pdf book_layer/.venv/bin/python -m unittest -v book_layer/tests/test_adapter.py
```
