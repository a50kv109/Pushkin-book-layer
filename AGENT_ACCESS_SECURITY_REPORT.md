# Отчёт по безопасности доступа агентов: Pushkin Rhyme Machine

**Дата аудита:** Ноябрь 2026  
**Область:** Безопасность программных интерфейсов (REST / MCP) при взаимодействии с ИИ-агентами.

---

## 1. Защита API-ключа Gemini

- **Текущее состояние:** В клиентском React-приложении `process.env.API_KEY` подставляется на этапе сборки Vite (`define` в `vite.config.ts`). При публичном размещении статического веб-бандла этот ключ становится виден в браузере.
- **Требование для Agent Gateway:** При реализации серверного шлюза (REST или MCP) обращение к `@google/genai` должно выполняться **строго на стороне бэкенда**. Клиентские агенты не должны иметь прямого доступа к секретному ключу Gemini.
- **Изоляция:** Переменная `GEMINI_API_KEY` считывается из серверного `.env` и никогда не возвращается в ответах эндпоинтов или логах.

---

## 2. Проблема вложенных вызовов («Агент вызывает Агента») и контроль расходов

- **Риск бесконечных циклов:** Если внешний агент (например, GPT-4) получает инструмент `generate_rhyme` и начинает передавать его вывод обратно на перепроверку в цикле, это может вызвать лавинообразный расход токенов Gemini API.
- **Меры предосторожности:**
  1. **Strict Idempotency & Rate Limiting:** Ограничение количества вызовов в минуту с одного IP/токена (например, не более 10 вызовов/мин).
  2. **Max Depth Flag:** Добавление метаданных в ответ (`"depth": 1`) для предотвращения рекурсивных повторных стилизаций.
  3. **Таймауты:** Жесткий таймаут на выполнение внешнего запроса к Gemini (10–15 секунд).

---

## 3. Валидация входных данных и защита от атак

1. **Лимит размера входа:**
   - Ограничить объем передаваемого текста до 4000 символов (достаточно для статьи или описания, но предотвращает DDoS и переполнение контекста LLM).
2. **Санитизация:**
   - Проверка типа данных (`string`), отсечение непечатных управляющих символов.
3. **Обработка сбоев upstream API:**
   - Корректная изоляция ошибок Gemini API (ошибки квот 429, таймауты 503) с возвратом структурированного JSON, без утечки стектрейса и внутренней конфигурации.

---

## 4. Разделение моделей развертывания

### Вариант А: Локальный инструмент (Рекомендуется для разработчика)
- Запуск локального MCP-сервера через `stdio` на рабочей машине.
- Доступен локальным агентам (Cursor, Claude Desktop, bash-агенты).
- Нулевой риск внешних сетевых атак, отсутствие затрат на хостинг.

### Вариант Б: Публичный REST API в сети
- Требует обязательного добавления:
  - API Gateway с проверкой Bearer-токенов (`Authorization: Bearer <secret>`).
  - CORS-политики.
  - Модуля Rate Limiting (Redis / In-memory leaky bucket).
  - Мониторинга биллинга Google Cloud / Gemini API.
